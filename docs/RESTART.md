默认检查只读取软件包元数据和资源，不导入 PyTorch。
GPU 检查由轻量父进程监控独立子进程，检查系统 RAM、GPU 总占用和温度，
并计入 Windows venv 启动器产生的子进程内存。
同目录 GPU 检查有互斥锁；该锁不覆盖其他工程，请勿并行启动其他训练。
启动 RAM ≥5120 MiB；运行 RAM ≥2048 MiB；GPU 总占用 ≤6700 MiB；
温度 <86℃；进程族峰值 RAM 总和 ≤10000 MiB。
每约 0.5 秒加一次查询耗时采样；不是硬件级硬限制，可能存在采样间瞬时峰值。
资源不足或代码异常记为技术失败，不判断方法无效。
每次验证独立写入 `outputs/smoke_<UTC时间>/`，不覆盖前次证据。

## 启动验证的含义

使用上游 `MultiModel_PL`、`SimCLRLoss`、`CDALoss`，原始模型维度不变。
输入四组合成数据，每组两名合成被试各三个窗口，共六个窗口；
六个窗口满足上游 top-5 指标至少五个候选的要求。
目标为上游训练步骤的 `sum(ISA_i) + 0.01 * CDA`。
分别检查两项目标有限、两项梯度有限且非零，再检查联合梯度和一次优化更新。

这四组合成输入不是 DASPS/SAM40/EEGMAT/DEAP，验证通过不代表配对正确、
损失收敛、跨被试泛化、焦虑预测有效或正式训练显存足够。
`config_restart.yaml` 是单卡启动验证配置，不是已适配的四源训练配置。
不直接执行原版 `run_pipeline.sh` / `train_multi.py`：
原版有服务器路径、固定 CUDA_VISIBLE_DEVICES 和 DDP 策略，还需单独适配。

## 已发现、不得忽略的问题

1. 原始 CDA 的 `cov_mat` 先交换 C/T 轴再 reshape 回 C/T，
   与直接沿时间计算通道协方差不一致。原版在基线里保留；
   必须通过手工小矩阵/NumPy 协方差对照后，在单独分支修复、记录公式差异。
   原版启动成功不意味着这一数学实现已正确。
2. 原始 ISA 把 batch 前后两半的相同位置作为正样本。不能仅凭相同窗口序号、
   情绪类别或“都是压力”就假定两个数据集/被试共享刺激。
   DEAP 的刺激身份、时间窗口对应也须在清洗记录中逐项验证。
   其他来源缺少证据时不得伪造 ISA 正样本；其用途需要重新登记。
3. 旧清洗数据可作为只读候选输入，但必须审计单位、真实/插值通道、
   trial/subject 身份、清洗拟合范围、QC 与划分后才能进入新训练。
   不因文件已存在而自动通过。
4. DASPS、SAM40、EEGMAT、DEAP 标签含义不同，不能混作 STAI-S。
   回归—排序应明确量表、排序关系来源、近似平分处理及被试独立评估；
   没有真实目标量表数据时不得宣称完成焦虑量化任务。
